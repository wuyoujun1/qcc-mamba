## P0 — 主表 S-Mamba 列与数据源不一致，且正文"持平"的说法站不住

**现象**：第五章定版 `paper/ch5/ch5cn_pdf.py` 里的 `OFF_SM`（表 2 的 S-Mamba 列）与数据源 `paper/ch5/data/第五章_主表消融_MSEMAE_20260904.md`（主表段，INDEX 里的权威数据源）对不上。

**证据**（30 个可比格）：
- 13 格一致或差 < 0.0002；**17 格不同**，其中 1 格差 > 0.005：
  `ETTh2 720`：md S-Mamba = **0.4084**，定版 = **0.4321**（Δ0.0075）
- **最要紧的两格**：定版正文（`ch5cn_pdf.py`）写
  > "在全部 36 个设置上，QCCK-M 在其中 34 个设置取得比 S-Mamba 更低的 MSE，其余两个设置即 **Exchange 在 720 与 Traffic 在 336** 与 S-Mamba **基本持平**。"

  但按 md 主表段，这两格 **QCC 是输的**：

  | 格 | QCC（md） | S-Mamba（md） | 定版 OFF_SM 填的值 |
  |---|---|---|---|
  | Exchange 720 | 0.8595 | **0.8581** | 0.8595 ← 等于 md 里的 QCC |
  | Traffic 336 | 0.4165 | **0.4154** | 0.4165 ← 等于 md 里的 QCC |

  即：定版在这两格的 S-Mamba 栏填的**正好是 QCC 自己的值**，于是变成"持平"。
- 按 md 主表段重新点数：**QCC 胜 32 / 负 2**（就是上面两格），不是"34 胜 2 平"。

**怎么解决**：
1. 回原始 log（工作副本 `/home/youjun/dataops_ws/logs/`）把 8 盘 × 4 步长的 S-Mamba 官方复现值重新导出，确定**哪一份是准的**；
2. 以准的那份统一 `OFF_SM`、`data/第五章_主表消融_MSEMAE_20260904.md` 与正文措辞；
3. 若 md 为准，正文必须改成"34 格中 32 格更优、Exchange 720 与 Traffic 336 两格略低于 S-Mamba"——**不能写"基本持平"**。

**为什么没直接改**：涉及"哪份数据是真的"，且会改到主表结论，需你拍板或回 log 重导。

## P1 — 论文正文与代码有 6 处对不上（清单见 README）

见 `README.md` 的「⚠️ 代码口径差异」第二节。摘要：

| 正文写法 | 代码实际 |
|---|---|
| 编码态经**两层相同的 U**演化 `U_v·U_v`（两层各含 CNOT） | 首层只旋转不纠缠，纠缠层数 = D−1，即 `D=2` 只有 **1 个** CNOT 层，且两层角度来源不同（H / S） |
| 振幅通道 `p(h_v)=softmax(W_r·h_v)` | 代码无 softmax 编码：`proj_H/proj_S` 是 `Linear(·→2N)`，输出直接当每比特 (θ,φ) 旋转角 |
| 投影矩阵/旋转角**逐变量独立可学习** | `proj_H`/`proj_S`/`W_q` 全变量**共享** |
| `H′ = LN(H + γ·H_p)` | 代码是 `H + γ·LN(H_p)`：有内层 LN、无外层 LN，位置相反 |
| 3.2 主频 `argmax_{f≥1}` 只忽略直流 | 实际跳过 k=0 **和 k=1** |
| `S_v` 恒 2M | 带 `--delay_in_s` 时 **2M+1**（脚本普遍开着） |
| 3.2 两级对齐是必备环节 | `--spectrum_time_align` / `--spectrum_freq_align` 默认**关** |

**怎么解决**：逐条决定「改代码」还是「改正文」。第三章已定稿，涉及第三章的几条基本意味着要改代码（或确认代码偏离是有意的）。
